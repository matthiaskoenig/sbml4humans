# CLAUDE.md - backend

The architecture of the `sbml4humans` package, the paths are relative to `backend/sbml4humans/`. The commands, the conventions and the error contract are in the `CLAUDE.md` of the repository root. Read `glossary/CLAUDE.md` before a change of `glossary.py`, `glossaryrules.py` or the report model.

**`backend/sbml4humans/api.py` - the http api.** A FastAPI app `api` with CORS open to every origin. Endpoints: `GET /api/examples` (metadata of the examples), `GET /api/examples/{id}` (report of an example), `POST /api/file` (upload), `GET /api/url` (download and report), `POST /api/content` (raw SBML in the body) and `GET /api/annotation_resource` (resolves an annotation resource via pymetadata). The lifespan handler loads the examples on startup. Report creation is synchronous and CPU bound, the async endpoint delegates to `run_in_threadpool`.

**`model.py`, `sbmlinfo.py`, `links.py` - the report.** `model.py` is the pydantic data model: one class per SBML object with the attributes of the specification (`Species`, `Reaction` with `SpeciesReference` and `KineticLaw`, the comp and fbc objects), `Model` with the SBML lists (`list_of_species`, ...), `Report{document, models, external_model_definitions, link_graph}`. The elements of a list stay in these fields; a ListOf container which states something of its own (a metaid, an SBO term, notes, an annotation, an id or a name) is a `ListOf{element, size}` in the `lists` of the element which owns it, with the list without its elements as its `xml`, and a plain list is not in the report. Python is snake_case, JSON camelCase (`model_dump(mode="json", by_alias=True)`). `sbmlinfo.SBMLDocumentInfo` walks the libsbml document and builds the objects, math as `Math{latex, formula}` (`mathml.py`) and units as latex (`units.py`), and records the symbols of every math. `links.build_link_graph` turns the report into `LinkGraph{nodes, edges}`: every SBase is a node with `pk = "<model id>/<type>:<id>"`, every reference (compartment, reactant, variable, units, math symbols, modelRef, port, flux bounds, ...) an `Edge{source, target, kind}` from the referencing to the referenced object, a `ListOf` a node which its owner names by a `listOf` edge and at which a comp reference by `metaIdRef` or `idRef` may end; unresolvable references are logged, never edges. A pk is local to one entry of an archive. `external.ExternalModels` resolves the comp `ExternalModelDefinition`s of all entries against each other (`resolution{status, entry, model, md5Matches}`, nothing is ever fetched), and `links.build_link_graphs` builds the graphs of all entries together, so that a replacement, a deletion or a port which reaches into an external model ends at the element of the other entry, as an edge with `targetEntry`. `schema.py` writes the JSON schema of `ReportResponse` to `frontend/src/schema/report.schema.json`, run it after every model change (the CI diffs it).

**`report.py` - the archive layer.** `report_for_path`/`report_for_bytes` accept SBML (plain or gzipped) and COMBINE archives (omex, one report per SBML entry of the manifest) and wrap the `Report` of every SBML entry with the manifest into a `ReportResponse`. An archive is read with `archive.read_omex`, never with `Omex.from_omex`: pymetadata adds the entries in the order of the file system, `read_omex` restores the order of the manifest, which is the order of the manifest and of the reports of a response. The reports are built first and linked together afterwards. `report_for_path(path, trusted=True)` also reads the files next to a single SBML file which its external model definitions name, as further entries; it is set for the shipped examples only and never for a path which holds the content of a request (upload, url, pasted content).

**`viewer.py`, `local.py`, `localstate.py`, `cli.py` - the python interface.** `viewer.show(path)` (exported as `sbml4humans.show`, the command `sbml4humans` of `cli.py`) finds the local server through the state file of `localstate.py` (port, pid, secret, version, in the user cache directory, mode 0600), starts `python -m sbml4humans.local` as a detached process if none of this version answers, posts the path and opens `/report?local=<token>`. `local.LocalApp` is an ASGI app which routes `/api/local/...` to its own endpoints (ping, reports by token, shutdown), every other `/api/...` to the public `api` unchanged and everything else to the built frontend (`resources/frontend/`, git ignored, `npm run build:package`, shipped in the wheel as a hatch artifact) with `index.html` as the fallback. It refuses a foreign `Host` or `Origin`, the endpoints which act on the machine need the secret, the report of a path is read trusted, and the server ends itself after `IDLE_TIMEOUT` without a request, which an open local report prevents by pinging. `localstate.py` imports nothing of the report, so that `import sbml4humans` stays cheap. Do not name a module `show`, it would shadow the function.
