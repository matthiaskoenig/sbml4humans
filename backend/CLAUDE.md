# CLAUDE.md - backend

The architecture of the `sbml4humans` package, the paths are relative to `backend/sbml4humans/`. The commands, the conventions and the error contract are in the `CLAUDE.md` of the repository root. Read `glossary/CLAUDE.md` before a change of `glossary.py`, `glossaryrules.py` or the report model.

**`backend/sbml4humans/api.py` - the http api.** A FastAPI app `api` with CORS open to every origin. Endpoints: `GET /api/examples` (metadata of the examples), `GET /api/examples/{id}` (report of an example), `POST /api/file` (upload), `GET /api/url` (download and report), `POST /api/content` (raw SBML in the body) `GET /api/annotation_resource` (the typed `AnnotationResource` through `resource_cache()`, cacheable by the browser for a day, 10 minutes with warnings and not at all with errors, as `ResourceCache` keeps it) and `GET /api/annotation_structure/{chebi}` (the ChEBI structure as sandboxed svg, 404 without one, the one answer outside the error contract). The validation of a source is answered apart from its report by `GET /api/validation/examples/{id}`, `POST /api/validation/file`, `GET /api/validation/url`, `POST /api/validation/content` and `GET /api/validation/upload/{id}` (a `ValidationResponse`, the sources, limits and trust of the report endpoints); the validation of an example is kept by `example_validations` unless a limit ended it. The lifespan handler loads the examples and starts the forkserver of the validations (`isolation.start_forkserver`, also by the local server) on startup. Report creation is synchronous and CPU bound, the async endpoint delegates to `run_in_threadpool`. `BodyLimitMiddleware` (inside the CORS middleware, so that its error responses carry the CORS headers) refuses a body beyond `limits.MAX_CONTENT_SIZE`, by its `Content-Length` or while it is read. `GZipMiddleware` (outermost, `add_gzip`) gzips every response of at least `GZIP_MINIMUM_SIZE` bytes at `GZIP_LEVEL` for a client which accepts it (the JSON of Recon3D: 109 MB, 5.8 MB gzipped). The report of an example is built on the first request for it and kept as gzipped JSON (`example_report_gzip`, an LRU of `EXAMPLE_CACHE_SIZE`), sent as it is or decompressed for a client without gzip; its `uid` is the one of the first request, the frontend does not use the uid.

**`limits.py`, `download.py` - what a request may make the server do.** `limits.py` holds the limits of the content of a request (`MAX_CONTENT_SIZE` of 100 MB, the `client_max_body_size` of nginx, for the body, the download, the decompressed gzip and the uncompressed archive, `MAX_ARCHIVE_ENTRIES`, `MAX_COMPRESSION_RATIO`, the download deadline and `MAX_REDIRECTS`) and `ContentTooLargeError`; the modules read them at the time they apply them, so that a test lowers them with `monkeypatch`. `download.download(url)` is the download of `GET /api/url`: http and https only, redirects followed one by one, and the connection is made by `PublicNetworkBackend`, an httpcore network backend which resolves the host, refuses it unless every address is public (`is_public`: no loopback, private, link local, shared, reserved, multicast or unspecified address, also not embedded in an IPv6 address) and connects to the address it checked, so that DNS rebinding finds no gap between check and connection. Every step (the name resolution, which runs in a daemon thread since `getaddrinfo` has no timeout, the connection, TLS, a read, a write) ends after `DOWNLOAD_STEP_TIMEOUT` or at the deadline of `DOWNLOAD_TIMEOUT`, whichever comes first. `SBML4HUMANS_ALLOW_PRIVATE_URLS=1` in the environment of the server allows every address, for the end to end tests alone, never set it for a server others reach.

**`annotations.py` - the annotation resources.** `resolve_resource(resource)` builds the typed `AnnotationResource` of one resource of an annotation (a url of identifiers.org or a MIRIAM urn) from `RDFAnnotationData` of pymetadata: the `collection` (prefix, name, homepage) and the `providers` of the registry of identifiers.org, the `identifier`, its `url` at the primary provider and `patternMatch`, the `ontology` term of OLS (label, IRI, ontology, OLS url, description, synonyms, cross references; the html tags some terms carry dropped by `_plain`), and `chebi` (formula, charge, mass, whether a structure exists, `ChebiQuery`) or `uniprot` (name, entry, organism, genes, length, function, `UniprotQuery`) for those collections; an unknown collection or a malformed resource raises `ValueError`, a term a web service does not know is a warning, a failed web service an error (the short `OLS_ERROR`, the raw message is logged). Every url of the resource (url, homepage, providers, IRI, OLS url, cross references) passes `_url`, which keeps http and https urls only and drops a provider without one. `ResourceCache` (one per process, `resource_cache()`) sits in front of the disk cache of pymetadata: a resolved resource lives 24 hours, one with warnings 10 minutes, one with errors is not kept, at most 5,000 entries (LRU), and concurrent requests of one resource share one lookup (`Future`), every waiter gets the result or the exception of the owner. The disk cache of pymetadata keeps the answers of OLS, ChEBI and UniProt 30 days and those of the registry one day, in `SBML4HUMANS_CACHE` (`configure_cache()` at import, production volume `cache`) or `~/.cache/pymetadata`. `MAX_RESOURCE_LENGTH` (2,000) limits the resource the api resolves and `CHEBI_ID` is the form of the id the structure endpoint accepts; the structure is the svg of `ChebiQuery.structure`, served with a sandboxing `Content-Security-Policy` and cacheable for 30 days, a 404 is `no-store`.

**`model.py`, `sbmlinfo.py`, `links.py` - the report.** `model.py` is the pydantic data model: one class per SBML object with the attributes of the specification (`Species`, `Reaction` with `SpeciesReference` and `KineticLaw`, the comp and fbc objects), `Model` with the SBML lists (`list_of_species`, ...), `Report{document, models, external_model_definitions, link_graph}`. The elements of a list stay in these fields; a ListOf container which states something of its own (a metaid, an SBO term, notes, an annotation, an id or a name) is a `ListOf{element, size}` in the `lists` of the element which owns it, with the list without its elements as its `xml`, and a plain list is not in the report. Python is snake_case, JSON camelCase (`model_dump(mode="json", by_alias=True)`). `sbmlinfo.SBMLDocumentInfo` walks the libsbml document and builds the objects, math as `Math{latex, formula}` (`mathml.py`, the xslt stylesheets compiled once per thread, since an lxml `XSLT` must not be shared between the threads of the threadpool) and units as latex (`units.py`, the rendering of a unit cached by its four numbers), and records the symbols of every math. `links.build_link_graph` turns the report into `LinkGraph{nodes, edges}`: every SBase is a node with `pk = "<model id>/<type>:<id>"`, every reference (compartment, reactant, variable, units, math symbols, modelRef, port, flux bounds, ...) an `Edge{source, target, kind}` from the referencing to the referenced object, a `ListOf` a node which its owner names by a `listOf` edge and at which a comp reference by `metaIdRef` or `idRef` may end; unresolvable references are logged, never edges. A pk is local to one entry of an archive. `external.ExternalModels` resolves the comp `ExternalModelDefinition`s of all entries against each other (`resolution{status, entry, model, md5Matches}`, nothing is ever fetched), and `links.build_link_graphs` builds the graphs of all entries together, so that a replacement, a deletion or a port which reaches into an external model ends at the element of the other entry, as an edge with `targetEntry`. `schema.py` writes the JSON schemas of `ReportResponse`, of `AnnotationResource` and of `ValidationResponse` to `frontend/src/schema/report.schema.json`, `annotation.schema.json` and `validation.schema.json`, run it after every model change (the CI diffs it).

**`odes.py` - the differential equations.** `ode_system(doc, model, documents, location)` builds the `OdeSystem` of the report from the typed target of sbmlode: `_Links` resolves a `Symbol.source` of sbmlode to a pk with `links.ModelIndex` (an SId, a local parameter through the kinetic law of its reaction, an element without an id through its metaid) and wraps the symbol as `\htmlData{pk=<pk>}{...}`, a symbol without an element (the ids a flattening of comp makes up) stays as it is; a failure is logged and returned as `ode_error`. `analyse` is the one entry into sbmlode, used by the report and by `report.ode_for_path` (the downloads `/api/ode/...` and `/api/local/ode/{token}`): `_ANALYSIS_LOCK` (libsbml aborts when two threads flatten comp models at once, `test_concurrent_analyses_of_comp_models`) and `validation.resolving_within(doc, documents, location)`, the confinement of the resolver of libsbml to the documents of the report which the validation uses as well (`test_external_model_of_a_request_reads_no_file`).

**`report.py` - the archive layer.** `report_for_path`/`report_for_bytes` accept SBML (plain or gzipped) and COMBINE archives (omex, one report per SBML entry of the manifest) and wrap the `Report` of every SBML entry with the manifest into a `ReportResponse`. The entries of an archive are in the order of its manifest (pymetadata 0.6.4 or later), which is the order of the manifest and of the reports of a response. The reports are built first and linked together afterwards. The archive of a report is extracted into a temporary directory of pymetadata's `Omex`, which is used as a context manager, so that nothing of a request stays on the server. The content of a path which is not trusted is read within `limits.py`: gzip is decompressed in chunks up to the limit, and an archive is checked for the number, the stated size and the compression ratio of its entries before it is extracted. `report_for_path(path, trusted=True)` also reads the files next to a single SBML file which its external model definitions name, as further entries; it is set for the shipped examples only and never for a path which holds the content of a request (upload, url, pasted content).

**`validation.py`, `isolation.py` - the validation of libsbml.** The report carries no validation: `report.validation_for_path(path, trusted)` answers `ValidationResponse{entries: {location: EntryValidation{issues, skipped}}, skipped}`, keyed like the reports; the response-level `skipped` is why the validation stopped early, also the reason of every entry it did not reach, and an entry it did not read is missing (all of them for `busy`). Every touch of libsbml is in the child: `report.validate_source(SourceJob{path, trusted, budget, limits})` reads the source like `report_for_path` (without the link graph), yields the locations first, then per entry the read issues and `skipped="expandedSize"` for an entry with submodel instances which expands to more than `MAX_EXPANDED_ELEMENTS` (10,000) elements (its own plus `instantiated_elements`: per submodel instance along every level the elements of the instantiated model, counted by `SBMLDocumentInfo.elements` per pk scope; one instance makes the comp validator flatten the whole model, a document without instances is never skipped), else the issues of `validate`. An issue goes to the element which starts closest before its line and column (`ElementPositions`). `isolation.run_isolated(function, argument)`: forkserver with `sbml4humans.forkserver` (numpy single threaded, so children start small) and `sbml4humans.report` preloaded (spawn where there is none), one child per request, the source passed as the path of a file the server keeps until the child ends (never libsbml objects), `VALIDATION_TIMEOUT` (60 s from the call on, reading the source and the wait for a child included) after which the child is killed and the rest is `"timeout"`, `RLIMIT_AS` of `VALIDATION_MEMORY` (2 GiB) whose `MemoryError` or `std::bad_alloc` abort is `"memory"` (an abort counts as memory only when the C++ runtime wrote its line of an uncaught `std::bad_alloc` to the standard error of the child, which the child writes to a file of its temporary directory and the server reads after its end and logs, its last 4 KiB with the control characters escaped), any other abnormal end of the child (another signal, also the SIGKILL of the OOM killer, another abort, an exit without its results) keeps the results it sent and is `"crashed"` for the rest, `RLIMIT_CPU` of twice the timeout (a backstop when the server dies without ending the child), the temporary files of the child (the archive pymetadata extracts, `tempfile` and `TMPDIR`/`TEMP`/`TMP` for native libraries) in a directory the server makes per child and removes when it has ended, also when it was killed or aborted, at most `MAX_CONCURRENT_VALIDATIONS` children (`SBML4HUMANS_VALIDATIONS`, 2 in production, else `os.process_cpu_count() // 2`, the cpu affinity, which a docker cpu quota does not change; a semaphore per server process, `--workers N` multiplies it), a call which gets no child while at least `MIN_CHILD_TIME` (1 s) of its timeout is left is `"busy"` without a child, so `"timeout"` is always a child which ran out of time, an exception of the child is raised in the server with the child traceback as a note. The api admits `admission_capacity()` validations (`MAX_CONCURRENT_VALIDATIONS + MAX_WAITING_VALIDATIONS`), answers a further one at once as busy (`api.run_validation`, before anything else of the request: `GET /api/validation/url` downloads after the admission) and waits for each in a thread of its own limiter (`validation_limiter`), never in the threadpool of the other endpoints. A validation whose client disconnects is cancelled: `run_validation` watches the receive channel of the request for `http.disconnect` and sets an event which `isolation.run_cancellable` hands to `run_isolated` (a context variable of the thread), which checks it every `CANCEL_INTERVAL` (0.1 s) while it waits for a child or for a result, kills the child and raises `ValidationCancelledError`; the admission and the run directory are freed at once (the download of `GET /api/validation/url` is not cancelled). An endpoint of a validation therefore takes the `Request`. The limits are read when they apply, so that a test lowers them with `monkeypatch`; a child of the forkserver does not see a `monkeypatch` of the server, so it gets the limits of `limits.py` in `SourceJob.limits` (`limits.ContentLimits`). Importing `validation.py` installs `ReportResolver` as the one resolver of libsbml, which during a validation answers only the documents of the report (`ReportDocuments`).

**`viewer.py`, `local.py`, `localstate.py`, `cli.py` - the python interface.** `viewer.show(path)` (exported as `sbml4humans.show`, the command `sbml4humans` of `cli.py`) finds the local server through the state file of `localstate.py` (port, pid, secret, version, in the user cache directory, mode 0600), starts `python -m sbml4humans.local` as a detached process if none of this version answers, posts the path and opens `/report?local=<token>`. `local.LocalApp` is an ASGI app which routes `/api/local/...` to its own endpoints (ping, reports by token, the validation of the path of a report by its token at `/api/local/validation/{token}`, shutdown), every other `/api/...` to the public `api` unchanged (the local endpoints and the frontend gzipped like the api) and everything else to the built frontend (`resources/frontend/`, git ignored, `npm run build:package`, shipped in the wheel as a hatch artifact) with `index.html` as the fallback. It refuses a foreign `Host` or `Origin`, below `/api/` a `Sec-Fetch-Site` other than `same-origin` or `none` and, from a client which states neither header (the python client of `show`), every request outside `/api/local/`, the endpoints which act on the machine need the secret, the report of a path is read trusted, its error responses carry the traceback (`api.TRACEBACK_STATE`), `GET /api/url` downloads from public addresses alone like the public api, and the server ends itself after `IDLE_TIMEOUT` without a request, which an open local report prevents by pinging. `localstate.py` imports nothing of the report, so that `import sbml4humans` stays cheap. Do not name a module `show`, it would shadow the function.
