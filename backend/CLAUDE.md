# CLAUDE.md - backend

The architecture of the `sbml4humans` package, the paths are relative to `backend/sbml4humans/`. The commands, the conventions and the error contract are in the `CLAUDE.md` of the repository root. Read `glossary/CLAUDE.md` before a change of `glossary.py`, `glossaryrules.py` or the report model.

**`backend/sbml4humans/api.py` - the http api.** A FastAPI app `api` with CORS open to every origin. Endpoints: `GET /api/examples` (metadata of the examples), `GET /api/examples/{id}` (report of an example), `POST /api/file` (upload), `GET /api/url` (download and report), `POST /api/content` (raw SBML in the body) `GET /api/annotation_resource` (the typed `AnnotationResource` through `resource_cache()`, cacheable by the browser for a day, 10 minutes with warnings and not at all with errors, as `ResourceCache` keeps it) and `GET /api/annotation_structure/{chebi}` (the ChEBI structure as sandboxed svg, 404 without one, the one answer outside the error contract). The validation of a source is answered apart from its report by `GET /api/validation/examples/{id}`, `POST /api/validation/file`, `GET /api/validation/url`, `POST /api/validation/content` and `GET /api/validation/upload/{id}` (a `ValidationResponse`, the sources, limits and trust of the report endpoints); the validation of an example is kept by `example_validations` unless a limit ended it. The lifespan handler loads the examples and starts the forkserver of the children (`isolation.start_forkserver`, also by the local server) on startup. The four report endpoints of a request answer the gzipped JSON their child built (`report.report_gzip_for_bytes` through `run_report`, the bytes as they are for a client which accepts gzip and decompressed in the threadpool by `report_response` for one which does not, which answers the report of an example as well; `GET /api/url` downloads after the admission, in the thread of its report, `report_of_download` like `validation_of_download`), and `POST /api/upload` vets its content through a child before the store keeps it; `run_report` admits and cancels a report as `run_validation` does a validation (`_run_admitted`, the thread of `report_limiter`, the admission of `isolation.REPORT_BUDGET`), but a report beyond the admission, like one whose client left, is an error of the contract and no `skipped`, since the report is the answer of its request. The ODE downloads of a request (`POST /api/ode/file`, `GET /api/ode/url`, `POST /api/ode/content`, `GET /api/ode/upload/{id}`) read the same untrusted content through sbmlode and libsbml, so they go through a child of the same budget (`report.ode_for_bytes` through `run_report` with `work="ode system"`, so that an interrupted one names the ODE system and never a report, and `ode_of_download` admits before it downloads), while `GET /api/ode/examples/{id}` writes its file in the process of the server. The endpoints keep `response_model=ReportResponse`, which FastAPI skips for an endpoint which returns a `Response`, so the OpenAPI document and the schema stay as they are. `BodyLimitMiddleware` (inside the CORS middleware, so that its error responses carry the CORS headers) refuses a body beyond `limits.MAX_CONTENT_SIZE`, by its `Content-Length` or while it is read. `GZipMiddleware` (outermost, `add_gzip`) gzips every response of at least `GZIP_MINIMUM_SIZE` bytes at `GZIP_LEVEL` (which is `report.REPORT_GZIP_LEVEL`, the one level every report is compressed at) for a client which accepts it (the JSON of Recon3D: 109 MB, 5.8 MB gzipped). The report of an example is built in the server process, on the first request for it, and kept as gzipped JSON (`example_report_gzip`, an LRU of `EXAMPLE_CACHE_SIZE`); its `uid` is the one of the first request, the frontend does not use the uid.

**`native.py` - the optional pure Rust source reader.** `SBML4HUMANS_PARSER=auto` selects an installed extension supporting `report/1` and `source/1`; `rust` requires it and `python` selects the compatibility path. `ReportJob.parser` captures this preference before the job enters the forkserver. `report.report_gzip` uses native serialized bytes directly for untrusted sources, within the same source limits and isolated worker budget; a native parse failure never retries through Python. Trusted directory reports, libSBML validation and Rust-generated ODE downloads retain the Python path. The production Docker image builds a native wheel from the same pinned revision as the browser package.

**`limits.py`, `download.py` - what a request may make the server do.** `limits.py` holds the limits of the content of a request (`MAX_CONTENT_SIZE` of 100 MB, the `client_max_body_size` of nginx, for the body, the download, the decompressed gzip and the uncompressed archive, `MAX_ARCHIVE_ENTRIES`, `MAX_COMPRESSION_RATIO`, the download deadline and `MAX_REDIRECTS`) and `ContentTooLargeError`; the modules read them at the time they apply them, so that a test lowers them with `monkeypatch`. `download.download(url)` is the download of `GET /api/url`: http and https only, redirects followed one by one, and the connection is made by `PublicNetworkBackend`, an httpcore network backend which resolves the host, refuses it unless every address is public (`is_public`: no loopback, private, link local, shared, reserved, multicast or unspecified address, also not embedded in an IPv6 address) and connects to the address it checked, so that DNS rebinding finds no gap between check and connection. Every step (the name resolution, which runs in a daemon thread since `getaddrinfo` has no timeout, the connection, TLS, a read, a write) ends after `DOWNLOAD_STEP_TIMEOUT` or at the deadline of `DOWNLOAD_TIMEOUT`, whichever comes first. `SBML4HUMANS_ALLOW_PRIVATE_URLS=1` in the environment of the server allows every address, for the end to end tests alone, never set it for a server others reach.

**`annotations.py` - the annotation resources.** `resolve_resource(resource)` builds the typed `AnnotationResource` of one resource of an annotation (a url of identifiers.org or a MIRIAM urn) from `RDFAnnotationData` of pymetadata: the `collection` (prefix, name, homepage) and the `providers` of the registry of identifiers.org, the `identifier`, its `url` at the primary provider and `patternMatch`, the `ontology` term of OLS (label, IRI, ontology, OLS url, description, synonyms, cross references; the html tags some terms carry dropped by `_plain`), and `chebi` (formula, charge, mass, whether a structure exists, `ChebiQuery`) or `uniprot` (name, entry, organism, genes, length, function, `UniprotQuery`) for those collections; an unknown collection or a malformed resource raises `ValueError`, a term a web service does not know is a warning, a failed web service an error (the short `OLS_ERROR`, the raw message is logged). Every url of the resource (url, homepage, providers, IRI, OLS url, cross references) passes `_url`, which keeps http and https urls only and drops a provider without one. `ResourceCache` (one per process, `resource_cache()`) sits in front of the disk cache of pymetadata: a resolved resource lives 24 hours, one with warnings 10 minutes, one with errors is not kept, at most 5,000 entries (LRU), and concurrent requests of one resource share one lookup (`Future`), every waiter gets the result or the exception of the owner. The disk cache of pymetadata keeps the answers of OLS, ChEBI and UniProt 30 days and those of the registry one day, in `SBML4HUMANS_CACHE` (`configure_cache()` at import, production volume `cache`) or `~/.cache/pymetadata`. `MAX_RESOURCE_LENGTH` (2,000) limits the resource the api resolves and `CHEBI_ID` is the form of the id the structure endpoint accepts; the structure is the svg of `ChebiQuery.structure`, served with a sandboxing `Content-Security-Policy` and cacheable for 30 days, a 404 is `no-store`.

**`model.py`, `sbmlinfo.py`, `links.py` - the report.** `model.py` is the pydantic data model: one class per SBML object with the attributes of the specification (`Species`, `Reaction` with `SpeciesReference` and `KineticLaw`, the comp and fbc objects), `Model` with the SBML lists (`list_of_species`, ...), `Report{document, models, external_model_definitions, link_graph}`. The elements of a list stay in these fields; a ListOf container which states something of its own (a metaid, an SBO term, notes, an annotation, an id or a name) is a `ListOf{element, size}` in the `lists` of the element which owns it, with the list without its elements as its `xml`, and a plain list is not in the report. Python is snake_case, JSON camelCase (`model_dump(mode="json", by_alias=True)`). `sbmlinfo.SBMLDocumentInfo` walks the libsbml document and builds the objects, math as `Math{latex, formula}` (`mathml.py`, the xslt stylesheets compiled once per thread, since an lxml `XSLT` must not be shared between the threads of the threadpool, and the latex of a math kept by `_LatexCache`, which every thread shares behind one lock and which is bounded in bytes, `MAX_LATEX_CACHE_BYTES` of 32 MiB per worker process, not in entries, since one math is as large as its file allows) and units as latex (`units.py`, the rendering of a unit cached by its four numbers), and records the symbols of every math. `derived_units` is the one caller of `getDerivedUnitDefinition()` and it is gated per model: the unit inference of libsbml builds the units of a whole model on the first element of it which is asked, recursing over every math of the model and into the body of every function definition a math calls, so `model()` measures the maths of the model before it builds its first element (`_unit_inference_maths`, every element of the core which carries one, the maths of the packages reach no unit inference; `mathml.math_depth` with the expanded depth of every function definition from `mathml.function_depths`) and leaves the optional `derived_units` of every element of that model absent, with one warning, where a math costs more than `MAX_UNIT_INFERENCE_DEPTH` (5,000) levels of recursion or where the function definitions hold a cycle, whose expansion has no depth; otherwise `getDerivedUnitDefinition()` overflows the stack of libsbml and the process dies outside the error contract. The gate starts closed, so a builder called without its model asks libsbml nothing. `links.build_link_graph` turns the report into `LinkGraph{nodes, edges}`: every SBase is a node with `pk = "<model id>/<type>:<id>"`, every reference (compartment, reactant, variable, units, math symbols, modelRef, port, flux bounds, ...) an `Edge{source, target, kind}` from the referencing to the referenced object, a `ListOf` a node which its owner names by a `listOf` edge and at which a comp reference by `metaIdRef` or `idRef` may end; unresolvable references are logged, never edges. A pk is local to one entry of an archive. `external.ExternalModels` resolves the comp `ExternalModelDefinition`s of all entries against each other (`resolution{status, entry, model, md5Matches}`, nothing is ever fetched), and `links.build_link_graphs` builds the graphs of all entries together, so that a replacement, a deletion or a port which reaches into an external model ends at the element of the other entry, as an edge with `targetEntry`. `schema.py` writes the JSON schemas of `ReportResponse`, of `AnnotationResource` and of `ValidationResponse` to `frontend/src/schema/report.schema.json`, `annotation.schema.json` and `validation.schema.json`, run it after every model change (the CI diffs it).

**`odes.py` - the differential equations.** `analyse` adapts original admitted XML bytes and a closed set of companion documents to `sbmlsim_core.OdeSystem`. Rust owns the reader, comp expansion, equation plan, printers and templates. `ode_system` supplies opaque SId, local-parameter and metadata keys from `ModelIndex`, then validates the resulting JSON against the report schema. Expected input failures log one warning without a traceback; unexpected analysis/conversion errors retain their traceback. The report and `report.ode_for_path` share this adapter. Source bytes are supplied lazily by `ReportDocuments`, preserving precision without libSBML reserialization. The generator releases the GIL and uses no global analysis lock. Import it lazily at the analysis/download boundary: validation workers preload `report`, and loading the simulator allocator there consumes their address-space budget before validation begins. Trusted path discovery belongs to the shared native core; request inputs supply explicit sources and never cause filesystem or network resolution.

**`report.py` - the archive layer.** `report_for_path`/`report_for_bytes` accept SBML (plain or gzipped) and COMBINE archives (omex, one report per SBML entry of the manifest) and wrap the `Report` of every SBML entry with the manifest into a `ReportResponse`. The entries of an archive are in the order of its manifest (pymetadata 0.6.4 or later), which is the order of the manifest and of the reports of a response. The reports are built first and linked together afterwards. The archive of a report is extracted into a temporary directory of pymetadata's `Omex`, which is used as a context manager, so that nothing of a request stays on the server. The content of a path which is not trusted is read within `limits.py`: gzip is decompressed in chunks up to the limit, and an archive is checked for the number, the stated size and the compression ratio of its entries before it is extracted. `report_for_path(path, trusted=True)` also reads the files next to a single SBML file which its external model definitions name, as further entries; it is set for the shipped examples and for the path the local server of `show` is given, never for a path which holds the content of a request (upload, url, pasted content). The report of a source which is not trusted is built in a child process: `report_gzip_for_bytes(content)` runs `report_gzip(ReportJob{path, trusted, limits, budget})` with `isolation.REPORT_BUDGET` and answers the JSON of the `ReportResponse` gzipped at `REPORT_GZIP_LEVEL` (which `api.GZIP_LEVEL` is, since `api` imports `report` and not the reverse), so that a document which ends the process of libsbml is an error of one request; a run which the child did not finish raises `ReportInterruptedError(interruption, work)`, whose message is the one sentence of `_INTERRUPTIONS` of that work the client reads. The JSON is written and compressed in the child, which carries even the largest report over the pipe in a few megabytes instead of a hundred (Recon3D: 109 MB of JSON, 5.8 MB gzipped), and the server passes those bytes on without ever holding the whole of a report. The ODE file of a source which is not trusted is written in a child of the same budget: `ode_for_bytes(content, fmt, location)` runs `ode_source(OdeJob{path, trusted, limits, fmt, location, budget})`, which reads the source as `ode_for_path` does and sends the small `OdeFile` back pickled, as the results of a validation are. `report_for_path` and `ode_for_path` keep building in the process of the server and keep their typed result for a trusted caller, the examples (`examples.py`) and the local server of `show` (`local.py`), and `report_for_bytes` and `report_for_sbml` build an untrusted source in the process of their caller, which no endpoint is any more and only the tests are. The equations of an entry are gated by the expanded size of that entry, as the validation of it is: `_expanded_size(entries, location)` is the elements of the entry plus those its submodel instances add (`validation.instantiated_elements`), None for an entry which instantiates nothing and is bounded by no budget however many elements it has, and an entry beyond the budget is not flattened - `_odes` gives it `_NOT_FLATTENED` as its `ode_error` and keeps every element of its report, `ode_for_path` raises it as a `ValueError` of the contract. The flattening of libsbml clones every instantiated element into one model (`Submodel::instantiate` per instance, per level), so its memory grows with the expanded size and not with the document: the fan out of 222,268 elements of a 3 KB document needs 5.2 GiB of address space where the rest of its report needs 1 GiB, and one level more needs more than 14 GiB, which is why the budget and not a larger `REPORT_BUDGET.memory` is the answer. The budget travels in `ReportJob.budget` and `OdeJob.budget`, read from `validation.MAX_EXPANDED_ELEMENTS` when the work is asked for, since a child of the forkserver does not see what a test changed in the server; `report_for_path(path, trusted, budget)` and `ode_for_path(..., budget=...)` take it, by default that constant.

**`validation.py`, `isolation.py` - the validation of libsbml and the children of a request.** The report carries no validation: `report.validation_for_path(path, trusted)` answers `ValidationResponse{entries: {location: EntryValidation{issues, skipped}}, skipped}`, keyed like the reports; the response-level `skipped` is why the validation stopped early, also the reason of every entry it did not reach, and an entry it did not read is missing (all of them for `busy`). Every touch of libsbml is in the child: `report.validate_source(SourceJob{path, trusted, budget, limits})` reads the source like `report_for_path` (without the link graph), yields the locations first, then per entry the read issues and `skipped="expandedSize"` for an entry with submodel instances which expands to more than `MAX_EXPANDED_ELEMENTS` (10,000) elements (its own plus `instantiated_elements`: per submodel instance along every level the elements of the instantiated model, counted by `SBMLDocumentInfo.elements` per pk scope; one instance makes the comp validator flatten the whole model, a document without instances is never skipped), else the issues of `validate`. An issue goes to the element which starts closest before its line and column (`ElementPositions`). `isolation.run_isolated(function, argument, budget)` runs the work of a request in a child process, the validation with `isolation.VALIDATION_BUDGET` (an `isolation.Budget` per kind of work, which holds its name, its timeout, its memory, its variable, its concurrency and its waiting, and whose children, admission and semaphore are its own, so that one kind of work never starves the other): forkserver with `sbml4humans.forkserver` (numpy single threaded, so children start small) and `sbml4humans.report` preloaded (spawn where there is none), one child per request, the source passed as the path of a file the server keeps until the child ends (never libsbml objects), the timeout of its budget (60 s from the call on, reading the source and the wait for a child included) after which the child is killed and the rest is `"timeout"`, `RLIMIT_AS` of its memory (2 GiB) whose `MemoryError`, `std::bad_alloc` abort or fatal line of the C library is `"memory"` (`_abnormal_end`: an abort counts as memory only when the C++ runtime wrote its line of an uncaught `std::bad_alloc` to the standard error of the child, `_BAD_ALLOC`, and a child which glibc ended itself because it could not place the thread-local storage of a library writes `_OUT_OF_MEMORY` and exits 127 without a signal, which is as common at the bound as the abort; the child writes its standard error to a file of its temporary directory and the server reads it after its end and logs it, its last 4 KiB with the control characters escaped), any other abnormal end of the child (another signal, also the SIGKILL of the OOM killer, another abort, an exit without its results) keeps the results it sent and is `"crashed"` for the rest, `RLIMIT_CPU` of twice the timeout (a backstop when the server dies without ending the child), the temporary files of the child (the archive pymetadata extracts, `tempfile` and `TMPDIR`/`TEMP`/`TMP` for native libraries) in a directory the server makes per child and removes when it has ended, also when it was killed or aborted, at most its concurrency children (`SBML4HUMANS_VALIDATIONS`, 2 in production, else `os.process_cpu_count() // 2`, the cpu affinity, which a docker cpu quota does not change; a semaphore per server process, `--workers N` multiplies it), a call which gets no child while at least `MIN_CHILD_TIME` (1 s) of its timeout is left is `"busy"` without a child, so `"timeout"` is always a child which ran out of time, an exception of the child is raised in the server with the child traceback as a note. The api admits `admission_capacity(VALIDATION_BUDGET)` validations (its concurrency plus its waiting), answers a further one at once as busy (`api.run_validation`, before anything else of the request: `GET /api/validation/url` downloads after the admission) and waits for each in a thread of its own limiter (`validation_limiter`), never in the threadpool of the other endpoints. The report of a request and its ODE file run the same way with `isolation.REPORT_BUDGET`, which holds the values of their work (180 s, 4 GiB, `SBML4HUMANS_REPORTS`, 1 in production, else half the cpus, twice its concurrency waiting) and whose children, admission and semaphore are counted by its name alone, so that reports which fill their pool refuse no validation and validations none of the reports. What a client reads of a run of that budget which did not finish is in `report._INTERRUPTIONS`, one sentence per interruption and per kind of work, the report of a source or its ODE system, so that it names what the client asked for: a timeout names the seconds of the budget, a memory interruption names its bound (`report._memory_bound`, 4 GiB in production, MiB below a GiB so that a bound a test lowered does not read as 0 GiB), a crash says that the process which read the document ended unexpectedly, and a busy server says to try again in a moment. Work whose client disconnects is cancelled: `run_validation` and `run_report` watch the receive channel of the request for `http.disconnect` (`_cancel_on_disconnect`) and set an event which `isolation.run_cancellable` hands to `run_isolated` (a context variable of the thread), which checks it every `CANCEL_INTERVAL` (0.1 s) while it waits for a child or for a result, kills the child and raises `IsolatedRunCancelledError`; the admission and the run directory are freed at once (the download of `GET /api/validation/url` and of `GET /api/url` is not cancelled and holds its admission until it ends). An endpoint of a validation, of a report and of an ODE file therefore takes the `Request`. The limits are read when they apply, so that a test lowers them with `monkeypatch`; a child of the forkserver does not see a `monkeypatch` of the server, so it gets the limits of `limits.py` in `SourceJob.limits` (`limits.ContentLimits`). Importing `validation.py` installs `ReportResolver` as the one resolver of libsbml, which during a validation answers only the documents of the report (`ReportDocuments`).

**`viewer.py`, `local.py`, `localstate.py`, `cli.py` - the python interface.** `viewer.show(path)` (exported as `sbml4humans.show`, the command `sbml4humans` of `cli.py`) finds the local server through the state file of `localstate.py` (port, pid, secret, version, in the user cache directory, mode 0600), starts `python -m sbml4humans.local` as a detached process if none of this version answers, posts the path and opens `/report?local=<token>`. `local.LocalApp` is an ASGI app which routes `/api/local/...` to its own endpoints (ping, reports by token, the validation of the path of a report by its token at `/api/local/validation/{token}`, shutdown), every other `/api/...` to the public `api` unchanged (the local endpoints and the frontend gzipped like the api) and everything else to the built frontend (`resources/frontend/`, git ignored, `npm run build:package`, shipped in the wheel as a hatch artifact) with `index.html` as the fallback. It refuses a foreign `Host` or `Origin`, below `/api/` a `Sec-Fetch-Site` other than `same-origin` or `none` and, from a client which states neither header (the python client of `show`), every request outside `/api/local/`, the endpoints which act on the machine need the secret, the report of a path is read trusted, its error responses carry the traceback (`api.TRACEBACK_STATE`), `GET /api/url` downloads from public addresses alone like the public api, and the server ends itself after `IDLE_TIMEOUT` without a request, which an open local report prevents by pinging. `localstate.py` imports nothing of the report, so that `import sbml4humans` stays cheap. Do not name a module `show`, it would shadow the function.
