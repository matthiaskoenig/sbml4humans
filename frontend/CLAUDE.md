# CLAUDE.md - frontend

The architecture of the Vue frontend. The commands, the conventions and the error contract are in the `CLAUDE.md` of the repository root, the glossary which gives the frontend every name in `glossary/CLAUDE.md`.

`markdown-it` renders the descriptions of the glossary in the help dialog and `report/helpMarkdown.ts` alone imports it, so that it is loaded with the first dialog and with no other page. The element tables (sorting, selection, windowing above 200 rows), the dropdowns and the `v-tooltip` directive are own code. Every build fails on a JavaScript chunk above 500 kB (`chunkSizeLimit.ts`, a plugin of `vite.config.ts`, unit tested in `tests/unit/chunkSizeLimit.test.ts`); split a chunk which grows beyond it rather than raising the limit.

**`frontend/src`.** `api/` is the fetch client with the error contract (`ApiError`) and the report types, generated into `types/report.ts` by `npm run types`, and `annotations.ts`, the resolve queue of the annotation resources: one request per resource, at most `MAX_CONCURRENT_RESOLVES` in flight, a queued resolve is dropped once all its callers abort, a resource answered with errors (a web service failed) is not kept and asked again by the next resolve; it also defines `MAX_AUTO_RESOLVES`, the element-wide automatic resolve budget, which `components/misc/CvTermList.vue` applies, resolving at most that many of an element's shown resources before a "show all" or "resolve all" click. The resource is the typed `AnnotationResource` of `types/annotation.ts` (generated from `schema/annotation.schema.json` by `npm run types`), fetched by `getAnnotationResource` of `api/client.ts`; `annotationStructureUrl(chebi)` is the url of the svg of a ChEBI structure, which the card loads as an `<img>` and drops on an error. `components/misc/CvTermResourceList.vue` renders one `components/misc/AnnotationCard.vue` per resource with the state of its resolve, `AnnotationCardState`: `idle` (not requested, beyond the resolve budget), `loading`, `resolved` and `failed` (the request failed, the card says the resource could not be resolved). The card is cy3sbml like: the qualifier, the collection and the identifier as badges, which it shows in every state, the identifier always a link (the url of the resolved resource, else the resource or its identifiers.org url); then the warnings and errors, the OLS term (ontology, label, IRI, the first `SYNONYM_LIMIT` synonyms before a "show all", description), the ChEBI structure next to formula, charge and mass, the UniProt rows, the cross references and the providers. Every label is a concept of the glossary read with `conceptEntry(key)` (`annotation*`, `chebi*`, `uniprot*`), all text is Vue text, never `v-html`. `stores/` are the Pinia stores of the report and the examples. The report store requests the validation of a report once the report has loaded, with the same source (`ReportSource`; a file and a pasted content are sent again, the backend keeps no state), through the `get*Validation`/`post*Validation` twins of the report requests of `api/client.ts`; `validationState` is `pending`, `done` or `failed` (with `validationError`, an `ApiError`) and null without a report, a validation request the proxy refuses for the rate limit of the client (status 429, `ApiError.status`, a page of nginx outside the error contract which the client does not read) is `done` with every entry `busy`, `validationFor(location)` the `ValidationIndex` of an entry once it is done, an entry the answer leaves out taking the `skipped` of the answer (`busy` leaves out all of them), or `unanswered` where the answer gives no reason, so that it never reads as a valid document; `ValidationIndex.reloadable` is false for a file and pasted content, which a reload of the page loses, so that the words of `busy` ask to load it again rather than to reload. A newer load and `clear()` abort the pending request by its `AbortSignal`, and the answer of a load a newer one followed is dropped. `report/` holds `ReportIndex` (every element by pk, the `lists` of every element among them, the edges of the link graph; one per entry, `ReportIndex.forEntries` connects them so that an edge with `targetEntry` is an `ElementRef{pk, entry}` on both of its ends, kept apart from the edges inside the entry; immutable and free of the validation, it knows the structure the issues are folded by: `holderOf(pk)`, the element with a row of a table, a model or the document which holds an element without a row of its own), `validationIndex.ts` (`ValidationIndex`, the issues of one entry from its `ReportIndex` and its `EntryValidation`: `issues`, `skipped`, `issueCounts`, `issuesOf`, `heldIssuesOf`, `rowIssuesOf`, `worstSeverity`, `worstSeverityOfType`; an issue of a pk the report does not hold, which the local server may answer since it reads the file again, is counted and listed by its pk without a link), `context.ts` (`useReportIndex()` and `useValidationIndex()`, the indexes of the shown entry which `pages/ReportPage.vue` provides, the second null while the validation is pending or failed; a component never builds a pk), `search` and `query` (the search and the view state of the report page kept in the route query, `help` among them, the key of the open explanation, which `view.ts` opens with `openHelp`, closes with `closeHelp(mode)` and resolves to a route with `helpRoute`), `glossaryDetails.ts` (the types of an entry of `glossary-details.json` and `loadGlossaryDetails()`, one cached promise of the fetch of its url, which the build emits as a file of its own (`?url`) so that no chunk carries it, dropped when it rejects so that the next dialog tries again), `helpMarkdown.ts` (`renderHelpMarkdown(markdown, hrefOf)`: `markdown-it` with html and linkify off through an own DOMPurify instance, `glossary:` links rendered as `<a data-help-key>` with the href `hrefOf` gives them, every other scheme than `https:`, `http:` and `mailto:` refused and rendered as its text), `columns/` (the table columns per element type), `notes.ts` (the notes sanitised with DOMPurify down to the markup real notes use), `latex.ts` (KaTeX rendering, which imports the KaTeX stylesheet and `assets/latex.css` so that only the report page carries them, KaTeX a chunk of its own by the `codeSplitting` of `vite.config.ts`, a formula longer than `MAX_LATEX_LENGTH` shows as text until a "render formula" click renders it on demand, an option the inspector's display mode alone offers), `xml.ts` (the highlighting of the XML view, `components/misc/XmlView.vue`: a scanner in one pass and without a backtracking regular expression which splits the XML into tokens of a kind each, every character of the input in one token, the lines with their indentation, from which a wrapped line hangs, and the parts of an attribute value between which a `<wbr>` lets a url break, rendered as Vue text, never `v-html`) and `limitedList.ts` (the links, the rows of a nested table, the CV terms and their resources in the inspector show `LIST_LIMIT` entries before a "show all"). `docs.ts` holds `DOCS_URL`, the url of the documentation site, apart from `report/glossary.ts` so that the app bar and the footer of the home and examples pages do not pull the glossary into their chunks. `analytics.ts` builds the vue-gtag settings of the production build, a page view reports the path of the route without its query. `pages/` are the routed pages: home (upload, url, paste), examples, report; `/report?local=<token>` is the report of the local server of `sbml4humans.show`, which the page pings while it is open. `components/` is split into `layout/` (app bar, split panes, states), `input/` (the upload forms), `report/` (context bar, type bar, search, element tables), `inspector/` (attributes per type, links, annotations), `help/` and `misc/` (math, units, links, notes, xml, shared across the other groups). `help/` is the explanation of one entry: `HelpDialog.vue`, mounted once by the report page and driven by `help`, a native `<dialog>` with `showModal()` whose parts are `HelpSection`, `HelpTechnical`, `HelpRules`, `HelpAttributes` and `HelpMarkdown` (the async import which brings `markdown-it`, started with the details and answered by `HelpDescriptionText.vue`, the description as text, where its chunk cannot be loaded); `HelpLink.vue` is the link of the dialog itself (a real href, a plain left click handled in place, everything else left to the browser, `plainClick.ts`), `HelpLabel.vue` the label of the report which opens its entry and keeps its tooltip, `HelpButton.vue` the help icon for a place whose click is taken; `words.ts` holds the words which are the chrome of the dialog and not of the glossary. The labels which open it are the label of an attribute row, the type in the header of the inspector, the heading of a link group, the header of a column of a nested table (`HelpLabel`) and, as an icon, the header of a column of an element table, which sorts, and the heading of a section (`HelpButton`); the type bar, the element links and the type marks open nothing. The header of the inspector no longer links the reference page, the footer of the dialog does. A `ListOf` has no table: it is linked from the row `lists` of its owner in `inspector/AttributesColumn.vue` and, a list of the model, from the heading of the table of its elements in `report/ElementSection.vue`. `data/` holds the order, labels, colours and icons of the SBML element types and the edge kinds. `components/equations/` is the view of the differential equations (`view=equations` of the query, `report/ViewSwitch.vue` at the start of the type bar, whose types it hides): `EquationsView` with the notice of the unsupported constructs, one `EquationSection` per section of `Report.odeSystem` (the labels and the summaries are concepts of the glossary), `EquationRow` (KaTeX in `\displaystyle` with `links`, rendered when the row comes near the view, `IntersectionObserver`), `EquationEvent`, `OdeDownload` (the store resends the source like for the validation, `downloadOde`) and `EquationBlock`, the equations of an element in the inspector (`ReportIndex.equationsOf`). A symbol is an element with `data-pk`, which one click handler of the view selects; the symbols of the selected element are marked by a rule of a stylesheet of the view, so that a row rendered later is marked too. A search switches back to the tables.

**The narrow window.** One breakpoint, the `md` of Tailwind (768 px): the styles of a phone are `max-md:` variants, and what is not a style asks `useNarrow()` of `src/narrow.ts` (one `matchMedia` listener for the application). The one exception is `document-info` of `report/ContextBar.vue` (level, version and packages) in the app bar, which is `max-sm:hidden` (below 640 px): next to the selects of the entry and the model it would push the bar beyond a window of 360 px, so a phone leaves it to the inspector of the document while a narrow tablet still shows it. Below `sm` the name next to the logo of `layout/AppBar.vue` gives way as well where the context holds a select (`group-has-[select]`), the entry of an archive or the model, which the counts of the validation (`report/ValidationSummary.vue`) would otherwise squeeze to its first letters. `ValidationSummary` shows a quiet `validation-pending` chip with a spinner while the validation runs, `validation-failed` with the message of the `ApiError` as its tooltip, a click on it opens the inspector of the document, whose `inspector/ValidationFailure.vue` shows the message and the traceback behind "Show details" (`useValidationFailure()` of `context.ts`, which the report page provides), and once it is done the counts or the `validation-skipped` chip (the list of the document says `validation-no-match` where its filters leave no group), whose tooltip and the note of `inspector/ValidationList.vue` say why (`expandedSize`, `timeout`, `memory`, `crashed`, `busy`, which suggests trying again later, and `unanswered`), in the words of `report/validationWords.ts`, a short form for the chip and a long one for the note. On a narrow window `pages/ReportPage.vue` leaves `SplitPane` out and shows `InspectorPanel` in place of `report/ReportTables.vue` (the tables of the report in their one scroll, kept mounted with `v-show` so that their scroll position survives), opens without the model selected, hides the type bar while an element is selected and leaves the dense footer out; the inspector shows `inspector-back` in place of `inspector-close`. `TypeBar.vue` holds the types behind `type-bar-toggle`, `AppBar.vue` wraps the search into a row of its own and holds its links behind `app-bar-menu` below `lg`. At every width `ElementTable.vue` pins the first column, when it is the id, to the left edge of its scroll (`pinned`), one pixel beyond the edge and with the line at its right edge only while the table is scrolled sideways. `v-tooltip` shows nothing for the `mouseenter` a touch is followed by, nor for the `mouseenter` of a pointer which rests while the page changes under it (a closed dialog, a pane which opens), until that pointer moves. The end to end tests of the narrow window are `tests/e2e/mobile.spec.ts`, which the `mobile` project of Playwright (Pixel 7) alone runs.
