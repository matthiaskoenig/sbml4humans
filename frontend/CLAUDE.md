# CLAUDE.md - frontend

The architecture of the Vue frontend. The commands, the conventions and the error contract are in the `CLAUDE.md` of the repository root, the glossary which gives the frontend every name in `glossary/CLAUDE.md`.

`markdown-it` renders the descriptions of the glossary in the help dialog and `report/helpMarkdown.ts` alone imports it, so that it is loaded with the first dialog and with no other page. The element tables (sorting, selection, windowing above 200 rows), the dropdowns and the `v-tooltip` directive are own code.

**`frontend/src`.** `api/` is the fetch client with the error contract (`ApiError`) and the report types, generated into `types/report.ts` by `npm run types`, and `annotations.ts`, the resolve queue of the annotation resources: one request per resource, at most `MAX_CONCURRENT_RESOLVES` in flight, a queued resolve is dropped once all its callers abort; it also defines `MAX_AUTO_RESOLVES`, the element-wide automatic resolve budget, which `components/misc/CvTermList.vue` applies, resolving at most that many of an element's shown resources before a "show all" or "resolve all" click. `stores/` are the Pinia stores of the report and the examples. `report/` holds `ReportIndex` (every element by pk, the `lists` of every element among them, the edges of the link graph; one per entry, `ReportIndex.forEntries` connects them so that an edge with `targetEntry` is an `ElementRef{pk, entry}` on both of its ends, kept apart from the edges inside the entry), `search` and `query` (the search and the view state of the report page kept in the route query, `help` among them, the key of the open explanation, which `view.ts` opens with `openHelp`, closes with `closeHelp(mode)` and resolves to a route with `helpRoute`), `glossaryDetails.ts` (the types of an entry of `glossary-details.json` and `loadGlossaryDetails()`, one cached promise of the fetch of its url, which the build emits as a file of its own (`?url`) so that no chunk carries it, dropped when it rejects so that the next dialog tries again), `helpMarkdown.ts` (`renderHelpMarkdown(markdown, hrefOf)`: `markdown-it` with html and linkify off through an own DOMPurify instance, `glossary:` links rendered as `<a data-help-key>` with the href `hrefOf` gives them, every other scheme than `https:`, `http:` and `mailto:` refused and rendered as its text), `columns/` (the table columns per element type), `notes.ts` (the notes sanitised with DOMPurify down to the markup real notes use), `latex.ts` (KaTeX rendering, a formula longer than `MAX_LATEX_LENGTH` shows as text until a "render formula" click renders it on demand, an option the inspector's display mode alone offers) and `limitedList.ts` (the links, the rows of a nested table, the CV terms and their resources in the inspector show `LIST_LIMIT` entries before a "show all"). `analytics.ts` builds the vue-gtag settings of the production build, a page view reports the path of the route without its query. `pages/` are the routed pages: home (upload, url, paste), examples, report; `/report?local=<token>` is the report of the local server of `sbml4humans.show`, which the page pings while it is open. `components/` is split into `layout/` (app bar, split panes, states), `input/` (the upload forms), `report/` (context bar, type bar, search, element tables), `inspector/` (attributes per type, links, annotations), `help/` and `misc/` (math, units, links, notes, xml, shared across the other groups). `help/` is the explanation of one entry: `HelpDialog.vue`, mounted once by the report page and driven by `help`, a native `<dialog>` with `showModal()` whose parts are `HelpSection`, `HelpTechnical`, `HelpRules`, `HelpAttributes` and `HelpMarkdown` (the async import which brings `markdown-it`, started with the details and answered by `HelpDescriptionText.vue`, the description as text, where its chunk cannot be loaded); `HelpLink.vue` is the link of the dialog itself (a real href, a plain left click handled in place, everything else left to the browser, `plainClick.ts`), `HelpLabel.vue` the label of the report which opens its entry and keeps its tooltip, `HelpButton.vue` the help icon for a place whose click is taken; `words.ts` holds the words which are the chrome of the dialog and not of the glossary. The labels which open it are the label of an attribute row, the type in the header of the inspector, the heading of a link group, the header of a column of a nested table (`HelpLabel`) and, as an icon, the header of a column of an element table, which sorts, and the heading of a section (`HelpButton`); the type bar, the element links and the type marks open nothing. The header of the inspector no longer links the reference page, the footer of the dialog does. A `ListOf` has no table: it is linked from the row `lists` of its owner in `inspector/AttributesColumn.vue` and, a list of the model, from the heading of the table of its elements in `report/ElementSection.vue`. `data/` holds the order, labels, colours and icons of the SBML element types and the edge kinds.

**The narrow window.** One breakpoint, the `md` of Tailwind (768 px): the styles of a phone are `max-md:` variants, and what is not a style asks `useNarrow()` of `src/narrow.ts` (one `matchMedia` listener for the application). On a narrow window `pages/ReportPage.vue` leaves `SplitPane` out and shows `InspectorPanel` in place of `report/ReportTables.vue` (the tables of the report in their one scroll, kept mounted with `v-show` so that their scroll position survives), opens without the model selected, hides the type bar while an element is selected and leaves the dense footer out; the inspector shows `inspector-back` in place of `inspector-close`. `TypeBar.vue` holds the types behind `type-bar-toggle`, `AppBar.vue` wraps the search into a row of its own and holds its links behind `app-bar-menu` below `lg`. At every width `ElementTable.vue` pins the first column, when it is the id, to the left edge of its scroll (`pinned`), one pixel beyond the edge and with the line at its right edge only while the table is scrolled sideways. `v-tooltip` shows nothing for the `mouseenter` a touch is followed by. The end to end tests of the narrow window are `tests/e2e/mobile.spec.ts`, which the `mobile` project of Playwright (Pixel 7) alone runs.
